# 直播 App 产品需求文档

> 版本：v0.1（基于效果图梳理）
> 日期：2026-09-06
> 适用工程：`live_project/flutter_live_app` + `live_project/flutter_live_server`

## 0. 信息来源与边界

本文档根据用户提供的直播 App 效果图和当前 Flutter/FastAPI 工程整理。

效果图是视觉与交互参考，不是可执行指令；图片中的示例昵称、数字、装饰文案、头像和品牌标识均视为演示数据。只有本需求文档和用户明确提出的要求，才构成开发范围。任何无法从效果图确认的规则，按本文“待确认项”处理，不擅自扩展为支付、审核或商业化承诺。

## 1. 产品目标

将现有直播基础项目升级为深色、紫粉渐变、内容驱动的直播社区 App，完成以下核心闭环：

```text
启动 App → 浏览直播 → 进入直播间 → 查看/发送弹幕 → 关注主播/互动
    ↘ 动态广场 → 点赞/评论/分享
    ↘ 消息中心 → 查看互动与通知
    ↘ 我的 → 资料、设置、切换主题、退出登录
主播路径：开播入口 → 填写直播信息 → 权限 → 预览/推流 → 结束直播
```

首期重点是“页面可运行、状态可反馈、主流程可验收”。真实礼物支付、复杂推荐算法、连麦 PK 和内容审核不作为首期阻塞项。

## 2. 当前工程基线

### 已有能力

- Flutter Material 3、Riverpod、go_router、Dio、WebSocket。
- StatefulShellRoute 五分支底部导航。
- 直播房间列表、详情、播放页基础结构。
- 登录/注册、JWT、TokenStorage。
- FastAPI 直播房间接口、MySQL/Alembic、Redis 在线人数基础能力。
- 直播间弹幕 WebSocket 基础链路。
- `LiveEngine` 抽象、PlatformView 以及 iOS/macOS/Android 原生媒体插件边界。

### 与效果图的主要差距

- 当前首页仍是普通 Material 浅色列表，需改为“直播”首页、分类栏、Banner、两列直播卡片。
- 当前第二个 Tab 是发现占位页，需改为动态广场。
- 当前中央“开播”是一个普通 Tab，目标是底部中央悬浮 `+` 操作入口。
- 消息和我的页面仍是占位/简化页面。
- 设置页、直播间视觉层、主题切换、关注/点赞/分享等交互尚不完整。
- 直播媒体能力需以当前实际平台实现和测试结果为准；不能仅因页面上显示“直播中”就宣称真实推流/拉流已完成。

## 3. 用户与权限

### 观众

- 未登录：可浏览公开直播和动态；进入需要身份的互动操作时引导登录。
- 已登录：可关注、点赞、发送弹幕、查看消息、管理个人设置。

### 主播

- 已登录且授予摄像头/麦克风权限后，可创建直播间并开始直播。
- 结束直播后房间状态变为 `ended`，不再出现在直播列表。

### 管理/系统能力

- 服务端负责鉴权、房间状态、消息广播、在线人数和数据持久化。
- 图片/视频二进制不经过 FastAPI；继续使用媒体服务/CDN 或现有媒体插件边界。

## 4. 信息架构与页面

### 4.1 底部主导航

从左到右固定为：

1. 直播
2. 动态
3. 中央圆形 `+`（开播/发布操作菜单，不占普通 Tab 语义）
4. 消息
5. 我的

要求：当前项使用主题色高亮；底部栏半透明深色；中央按钮悬浮并使用渐变或主题主色；重复点击当前 Tab 回到该分支初始位置；直播间等全屏页面隐藏底部栏。

### 4.2 页面清单

| 页面 | 路由建议 | 优先级 | 说明 |
|---|---|---:|---|
| 直播首页 | `/home` | P0 | 直播分类、Banner、两列房间卡片 |
| 动态广场 | `/discover` | P0 | 关注/推荐/最新 Feed |
| 消息中心 | `/message` | P0 | 互动、系统、客服入口和会话列表 |
| 我的 | `/profile` | P0 | 资料卡、统计、VIP 占位、快捷入口、设置 |
| 直播间 | `/live-room/:roomId` | P0 | 视频/封面、弹幕、互动工具栏 |
| 设置 | `/settings` | P0 | 账号、安全、通知、隐私、主题、退出 |
| 开播表单 | `/create-live` | P0 | 标题、分类、主播信息、权限检查 |
| 主播控制台 | `/live-broadcast/:roomId` | P1 | 预览、推流状态、结束直播 |
| 搜索 | `/search` | P1 | 搜索主播、直播间、动态 |
| 关注列表/资料页 | `/user/:userId` | P1 | 主播资料和关注关系 |

## 5. 功能需求

### 5.1 直播首页（P0）

视觉结构：

- 深色背景，顶部状态栏安全区；标题“直播”、搜索按钮、通知按钮。
- 横向分类：推荐、颜值、新秀、才艺、女团、PK、语音；当前项有粉色/紫色下划线。
- 顶部推荐 Banner，支持图片、标题和点击跳转；无资源时使用渐变占位，不显示破图。
- 两列直播卡片：封面、直播中标签、主播名称、在线人数、分类/等级信息。
- 下拉刷新、分页或加载更多；加载、空态、错误、重试均需设计。

交互：

- 点击卡片进入直播间。
- 点击分类切换列表并保留当前分类状态。
- 点击搜索进入搜索页；点击通知进入消息中心或通知子页。

### 5.2 动态广场（P0）

- 顶部标题“动态”、通知入口；Tab：关注、推荐、最新。
- 推荐页展示图文/视频动态卡片：头像、昵称、等级、发布时间、正文、图片或视频、点赞/评论/分享数量。
- 顶部提供“关注动态”或同等语义的快捷入口；已关注状态可取消关注。
- 支持点赞切换、评论入口、分享入口；首期分享可使用系统分享或复制链接。
- 图片数量应支持 1/3/多图的自适应布局；视频无真实地址时显示封面和播放占位。

### 5.3 消息中心（P0）

- 顶部三类入口：互动消息、系统通知、官方客服。
- 会话列表展示头像、名称、最后一条消息、时间、未读数。
- 点击会话进入消息详情；进入后清除对应未读数。
- 未登录时可展示空态，并在需要身份的操作处引导登录。
- 消息状态至少包括未读、已读、加载失败和空列表。

### 5.4 我的（P0）

- 顶部背景使用主题渐变或弱化的个人背景图。
- 展示头像、昵称、认证/等级标识、用户 ID、签名和统计数据：关注、粉丝、获赞。
- VIP 卡片为可替换商业化占位：展示权益说明和“立即开通”按钮；首期不得接入真实支付。
- 快捷入口至少包含：我的钱包、我的等级、我的粉丝、我的贵族、我的动态、历史记录、我的收藏、我的访客。
- 设置列表：实名认证、青少年模式、帮助与反馈；设置按钮进入设置页。

### 5.5 直播间（P0）

- 竖屏全屏媒体区域，默认黑色/深色背景；媒体不可用时显示封面、加载态、错误态和重试。
- 顶部展示主播头像、名称、关注按钮、在线人数和关闭按钮。
- 弹幕从底部向上叠加，单条消息限制 200 字；支持连接中、连接失败、登录后可发送等状态。
- 底部操作：输入框“说点什么…”，礼物入口、分享、更多；右侧可显示点赞心形动画。
- 未登录用户可以观看公开内容，发送弹幕/关注时跳转登录。
- 不把礼物按钮误做成真实扣款：首期点击可弹出“功能准备中”或使用明确标注的 Mock 面板。

### 5.6 开播（P0/P1）

- 中央 `+` 点击后弹出操作菜单：开播、发布动态（发布动态可先置灰并标记规划中）。
- 开播表单：直播标题必填、分类选择、主播名称/用户信息、封面可选。
- 点击开始后按顺序执行：校验表单 → 请求摄像头/麦克风权限 → 创建房间 → 初始化媒体引擎 → 预览/推流 → 服务端确认 `living`。
- 任何一步失败都要保留可理解的错误信息和重试入口，不能留下“幽灵直播间”。
- 结束直播按顺序执行：停止推流 → 调用服务端结束房间 → 刷新直播列表 → 返回上一级。

### 5.7 设置与主题（P0）

- 设置项：账号与安全、消息通知、隐私设置、直播设置、通用设置、清理缓存、关于我们。
- 清理缓存展示当前缓存大小，二次确认后清理并反馈结果。
- 主题至少四种：默认（星夜紫）、甜美粉、清新蓝、自然绿；每个主题定义背景、表面、主色、强调色、文字和状态色。
- 主题切换即时生效，重启 App 后保持；不要只改按钮颜色而留下不可读的文字/分割线/输入框。
- 退出登录需二次确认；退出后清理本地 Token，并回到未登录态。

## 6. 视觉与交互规范

### 6.1 设计令牌（建议初始值）

| 令牌 | 默认值 | 用途 |
|---|---|---|
| background | `#0D0F1C` | 页面背景 |
| surface | `#171A2A` | 卡片/底部栏 |
| surfaceVariant | `#22253A` | 次级容器 |
| primary | `#E84DDB` | 主按钮、选中态 |
| secondary | `#8E5CF6` | 渐变、辅助强调 |
| textPrimary | `#FFFFFF` | 主文字 |
| textSecondary | `#A9AEC1` | 次级文字 |
| divider | `#2A2D40` | 分割线 |
| radiusCard | `16` | 卡片圆角 |
| radiusButton | `20` | 按钮圆角 |

### 6.2 适配要求

- 以常见 9:16 手机为基准，同时适配刘海/挖孔安全区、小屏和大屏。
- 所有横向列表使用可滚动容器；不要用固定宽度导致溢出。
- 图片使用 `BoxFit.cover`，头像使用圆形裁剪；网络图片失败提供本地/渐变占位。
- 触控区域建议不小于 44×44 logical pixels。
- 文本需要支持较长昵称、不同字体缩放和无障碍对比度。
- 动效短而克制：Tab 切换、点赞、心形飘浮、主题过渡；页面核心信息不可依赖动效才能理解。

## 7. 数据与接口需求

### 7.1 客户端模型

建议增加或完善：

- `UserProfile`：头像、昵称、用户 ID、签名、关注数、粉丝数、获赞数、认证、等级。
- `LiveCategory`：编码、名称、排序、是否选中。
- `BannerItem`：图片、标题、跳转目标。
- `FeedPost`：作者、正文、媒体、时间、点赞/评论/分享、当前用户是否点赞。
- `ConversationSummary`：会话类型、对象、预览、时间、未读数。
- `AppThemeId`：默认、粉、蓝、绿。

### 7.2 服务端接口建议

沿用现有统一响应格式和分层结构，新增接口可按下列语义实现：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/live/categories` | 直播分类 |
| GET | `/live/banners` | 首页 Banner |
| GET | `/live/rooms?category=&cursor=` | 分类直播列表 |
| GET/POST | `/users/me` | 读取/更新个人资料 |
| POST/DELETE | `/users/:id/follow` | 关注/取消关注 |
| GET | `/feed?tab=&cursor=` | 动态 Feed |
| POST/DELETE | `/feed/:id/like` | 动态点赞/取消点赞 |
| GET | `/messages/summary` | 消息摘要与未读数 |
| POST | `/messages/:id/read` | 标记已读 |
| GET/PUT | `/users/me/settings` | 设置读取/保存 |

首期允许用 `MockRepository` 完成动态、消息、个人资料和主题数据，但必须保留 Repository 接口，后续替换真实 API 时不改页面层。

### 7.3 一致性与安全

- 观众端不能拿到 `pushUrl`；推流地址只返回给主播控制台。
- 所有需要用户身份的 API 使用现有 JWT 机制。
- 关注、点赞、已读等操作需要幂等或具备明确的状态回滚策略。
- 弹幕仍通过 WebSocket；视频流不经过聊天连接。
- 图片、昵称、动态正文均按不可信外部数据处理，不允许拼接为可执行内容。

## 8. 状态、异常与埋点

每个 P0 页面必须覆盖：首次加载、刷新、空数据、加载失败、重试、网络断开、未登录、登录失效、超长文本、图片加载失败。

建议记录的产品事件：进入首页、切换分类、进入直播间、发送弹幕、点击关注、点赞动态、打开消息、切换主题、开始开播、结束开播。首期可先使用本地日志，不要求接入第三方分析平台。

## 9. 分阶段交付

### Phase 1：视觉骨架与导航（P0）

- 全局深色主题、四套主题令牌、底部五入口和中央 `+`。
- 首页、动态、消息、我的、设置页面达到效果图结构。
- 使用稳定 Mock 数据，完成 loading/empty/error 状态。

### Phase 2：观众闭环（P0）

- 直播列表分类、直播间视觉层、弹幕输入/展示、登录拦截。
- 关注、点赞、分享的本地状态与后端接口边界。

### Phase 3：主播闭环（P1）

- 开播表单、权限、媒体引擎、房间状态同步、结束直播和异常兜底。

### Phase 4：真实数据与增强能力（P1/P2）

- 动态/消息/资料真实 API、搜索、通知、关注列表。
- 礼物、VIP、支付、审核、连麦/PK、推荐算法等另立需求与安全评审。

## 10. 验收标准

- App 启动后默认进入“直播”首页；五个底部入口和中央 `+` 可用，直播间/设置返回栈正确。
- 首页在无网络时能显示错误和重试；有数据时以两列卡片展示；点击卡片可进入直播间。
- 动态 Tab 可在关注/推荐/最新间切换，至少一条 Mock 动态能完成点赞反馈。
- 消息中心能看到三类入口和会话未读数，进入后未读数清零。
- 我的页面展示资料、统计、快捷入口和设置入口；未登录能进入登录流程。
- 设置页切换四种主题后全局即时变化，重启后主题仍保持。
- 直播间能显示媒体加载/错误态、弹幕列表和发送结果；未登录发送时引导登录。
- 开播失败、权限拒绝、媒体失败、网络中断、返回退出等路径都有可恢复反馈。
- `flutter analyze`、Flutter 单测、服务端测试通过；不修改生成文件来绕过测试。
- UI 不出现明显溢出、不可读文字或点击区域过小的问题。
